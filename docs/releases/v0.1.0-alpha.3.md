There is no Remix runtime in this tree.

## Campaign commission

Hosted finalization, in basis points, for contests and giveaways:

| Plan    | Rate |
| ------- | ---: |
| Free    |  10% |
| Starter | 7.5% |
| Creator |   5% |
| Pro     |   0% |
| Teams   |   0% |
| Founder |   0% |

`SELF_HOSTED=true` on the server process sets every plan to 0%. The process does not create a
platform-fee invoice and does not require `OWNER_NWC` to finish a zero-fee campaign. Winner payouts
remain a separate payment from a connected creator wallet. A request header or account field cannot
select the self-hosted rate.

A paid invoice is not rewritten. An open invoice at or below the current quote is reused. A higher
open invoice is expired in the database and is not the amount due. The software does not send
refunds.

## Lightning payouts

The 16 November safeguards stay: exact BOLT11 amounts, mainnet and expiry checks, atomic claims,
unique payment hashes, `paying` and `unknown`, budget reservation, and referral payouts that stay
off unless `REFERRAL_PAYOUTS_ENABLED` is `true`, `1`, or `yes`.

This alpha adds:

- `pay_invoice` and the following `get_info` / `lookup_invoice` each have a deadline. If both stay
  unresolved, the payout is `unknown` and the worker continues.
- A payment is confirmed only when a 32-byte preimage hashes to the invoice payment hash.
- Human-readable errors, including the words "payment failed", are not treated as proof that no
  payment happened. Only specific NIP-47 codes are a definitive rejection.
- An operator cannot mark a `paying` or `unknown` attempt unpaid until its stored resolution
  deadline. That deadline is the payment timeout plus both reconciliation lookups plus a 30 second
  margin. The default is 105 seconds. The maximum configuration is 390 seconds. A row written before
  this column existed uses the 390 second budget. The command is
  `pnpm exec tsx scripts/resolve-campaign-payout.ts`. There is no unauthenticated HTTP route.

## Install verification

CI applies `prisma migrate deploy` to an empty PostgreSQL 17 database and checks plan rows and the
unique payout payment-hash index. The existing test job still uses `prisma db push` so it can load
the schema without replaying history. `pnpm test:relay-publish` still uses the in-repo publisher
against a disposable relay. The standalone Cloudflare publisher is not started by that test. See
[publisher integration](../operations/publisher-integration.md).

## Known limits

- Manual reconciliation depends on the operator reading the wallet. The two-minute hold reduces, and
  does not remove, the chance of paying twice after a lost reply.
- Companion repositories (publisher, Blastr, cache worker, Blossom) are not part of this commit.
  Follow [the companion handoff](../security/companion-handoff.md).
- Production was not deployed. No release tag was pushed. No mainnet payment was sent.
