# v1.0.0-beta.2

Unreleased candidate. Do not tag this file's commit to fill in the SHA. `v1.0.0-beta.1` stays at
`9b1e08cf9a8cf381b640d26c26277e2b0c5ad169`.

This prerelease is the application with the in-process Nostr publisher and the in-process Nostr read
cache. A self-hosted install does not need the Cloudflare publisher or the Cloudflare cache worker.
The legacy HTTP adapters remain available.

## Toolchain

- Node.js 26.13.1 or newer
- pnpm 12.21.0
- PostgreSQL and Redis

## What changed since v1.0.0-beta.1

- Signed events are published from this process when `SELF_HOSTED=true` or
  `NOSTR_PUBLISHER_BACKEND=internal`.
- Profile, thread, and social-graph reads run in this process, with Redis as the cache. NostrMash
  and public Primal sockets are still the default upstreams. Self-hosting the app does not operate
  an independent Nostr indexer.
- A retryable publish failure returns the scheduled row to `SCHEDULED`, so the next attempt can
  publish. A negative relay acknowledgement stays failed.
- `pnpm test:self-host-acceptance` boots the production server and worker and delivers a signed note
  to a loopback relay. `docker-compose.self-host.yml` is an optional container stack.
- Release validation treats the external publisher commit as optional unless `publisher_mode` is
  `http`.

## Migration

From `v1.0.0-beta.1`:

1. Pull the release commit. Do not move the beta.1 tag.
2. Run `pnpm install` and `pnpm exec prisma migrate deploy`.
3. For a self-hosted install, set `SELF_HOSTED=true`. Leave `NOSTR_PUBLISHER_URL` and
   `PRIMAL_CACHING_URL` empty unless you are keeping an HTTP adapter on purpose.
4. `NOSTR_PUBLISHER_ALLOW_PRIVATE_RELAYS` stays unset unless a relay is on a private network you
   operate.
5. Restart the web process and the worker together. One process on the old backend and one on the
   new backend is a different attempt, not a failover.

Hosted rollback is `NOSTR_PUBLISHER_BACKEND=http` with the previous publisher URL and token, or
`NOSTR_READ_BACKEND=legacy_http` with the previous cache URL. Change one backend at a time. Keep the
legacy workers until that rollback window has closed.

## Known limitations

- The tag SHA is filled in only after the tag exists, in a commit that is not the tagged commit.
- `/healthcheck` names the configured backend. It does not prove a relay accepted an event.
- Package version stays `1.0.0-beta.1` until this prerelease is published.
- Published prerelease tags do not receive security backports. Fixes land on `main`.
