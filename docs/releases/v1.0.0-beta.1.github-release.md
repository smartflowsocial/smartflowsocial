## What this is

SmartFlowSocial v1 — Now Open Source.

The first coordinated open-source release of SmartFlowSocial: a Nostr-native publishing platform you
can run yourself or use as a hosted service. The product was already in open beta. This tag does not
mean the project just launched.

You sign notes with your own NIP-07 or NIP-46 signer. The server stores the signed event and
publishes it later. It does not keep your Nostr private key. The source is under the Unlicense.
`package.json` stays `"private": true` so the package is not published to npm. That flag does not
make the GitHub repository private.

`SELF_HOSTED=true` on a server you operate sets the platform campaign commission to 0% on every plan
and does not apply hosted plan limits. The hosted service at https://smartflow.social is the same
application. Hosted campaign commission is Free 10%, Starter 7.5%, Creator 5%, and 0% on Pro, Teams,
and Founder. Winner payouts come from the creator's wallet.

## Components

Required for a scheduler that delivers notes:

- This application, at the commit above.
- The publisher in `smartflowsocial/smartflowsocial-publisher`, if notes should reach a relay.

Optional, and not tagged with this release:

- Blossom (`smartflowsocial/smartflowsocial-blossom`) for media.
- Blastr (`smartflowsocial/smartflowsocial-blastr`).
- Cache worker (`smartflowsocial/smartflowsocial-cache-worker`).
- The landing site (`smartflowsocial/smartflowsocial-landing`).

No companion release SHA was recorded. Current `main` in those repositories is not the version that
shipped with this tag. Production and staging deployment SHAs were not read from the running
services. They are unknown. A green GitHub Actions run is not a deployment SHA.

## Upgrade

```bash
pnpm exec prisma migrate deploy
```

That applies `20261117220000_owned_object_deletion`. Set `REFERRAL_PAYOUTS_ENABLED` explicitly if
referral payouts should continue. Publisher private relays require `ENVIRONMENT=test` or
`ENVIRONMENT=development`.

## Known limitations

Account deletion does not remove blobs from a Blossom server this deployment does not operate, and
it does not remove events relays have already accepted. `GET /cron/purge-retained-records` still
runs the purge when the cron secret matches. Prefer `POST`. The public contact is
`npub1ckqlguq0htvs3smwy8pl5uwmfas0h208p7p8hs92ghaurgkmzzrsw3vlh0`.
