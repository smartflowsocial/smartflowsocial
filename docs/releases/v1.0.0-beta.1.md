
`git rev-parse HEAD` must print `9b1e08cf9a8cf381b640d26c26277e2b0c5ad169`.

Node.js 26.13.1 or newer and pnpm 12.21.0. Then follow
[the self-host smoke](../getting-started/self-host-smoke.md). `main` is a different tree.

## What this prerelease is

1. **Nostr-native.** You sign events with your own NIP-07 or NIP-46 signer. The server stores the
   signed event and publishes it later. It does not need your Nostr private key.
2. **Open source and public domain.** The code is under the [Unlicense](../../LICENSE).
3. **Self-hostable.** `SELF_HOSTED=true` turns hosted plan limits off for the software you run and
   sets the platform campaign commission to 0% on every plan. No platform-fee invoice is created.
4. **Hosted option available.** The hosted service at [smartflow.social](https://smartflow.social)
   is the same application. Hosted campaign commission is Free 10%, Starter 7.5%, Creator 5%, and 0%
   on Pro, Teams, and Founder.

The hosted service is operated centrally. Scheduled signed events are stored until publication.
Hosted services may process metadata and media. An independent deployment does not depend on the
hosted operator for scheduling.

## What the tagged commit contains

- Owned media deletion is queued in `OwnedObjectDeletion` before the account row is removed. The
  worker retries those keys after a storage outage or a process restart. Shared objects, foreign
  keys, and Blossom blobs this install does not control are left in place.
- Blossom `/ready` treats a missing probe object as healthy and classifies other storage errors
  separately. On 17 November 2026 at 22:38 UTC, `https://blossom-api.smartflow.social/ready`
  returned HTTP 200 with `status: ready`, `storage: true`, and `storageProbe: missing`. That check
  did not upload, read, or delete an object, and it did not identify the deployed commit.
- `pnpm test:worker` in the publisher repository runs the Worker in `wrangler`'s local runtime
  against a loopback Nostr relay. It is separate from `pnpm smoke:publish` and from
  `pnpm test:relay-publish`.
- Blastr production publish is manual. Staging is configured to use `blastr-publish-jobs-staging`.
  The queue has to exist before a staging deploy. Creating it was not done as part of this tag.
- Incoming NWC lookups say whether settlement was proven with a preimage or only reported by the
  wallet. Outgoing payouts still require a matching preimage.

## Upgrade

From a checkout of the tag, apply migrations with `pnpm exec prisma migrate deploy`. The migration
added for this prerelease is `20261117220000_owned_object_deletion`.

`SELF_HOSTED` is read from the server environment. A request header, cookie, or query parameter
cannot select it.

`REFERRAL_PAYOUTS_ENABLED` must be `true`, `1`, or `yes` or referral payouts stay off. `OWNER_NWC`
does not turn them on.

Publisher `ALLOW_PRIVATE_RELAYS=true` does nothing unless `ENVIRONMENT` is `test` or `development`.
A production worker keeps the private-network block.

## Known limitations

- This is a prerelease. It is not stable `v1.0.0`.
- Production component SHAs were not read from the running services.
- Externally hosted Blossom objects are not deleted by account deletion. Relays keep events they
  have already accepted.
- The public contact is `npub1ckqlguq0htvs3smwy8pl5uwmfas0h208p7p8hs92ghaurgkmzzrsw3vlh0`.
- `GET /cron/purge-retained-records` still runs the purge when the cron secret matches, and the
  response sets `Deprecation: true`. Prefer `POST`. The in-process worker does not use the GET
  route.

## Release manifest

```bash
node scripts/release-manifest.mjs
node scripts/release-manifest.mjs --online
```

The offline command checks that this prerelease is recorded as published, that the application SHA
is the tag, that the SHA is not the commit which contains the manifest, and that companion and
production SHAs are still unknown. The online command prints each repository's current `main` commit
and labels it as an observation. It does not write those SHAs into the manifest.

Future releases use `node scripts/release-record.mjs --init <version>` so the record is created
after the tag exists, instead of storing the commit that adds the file.
