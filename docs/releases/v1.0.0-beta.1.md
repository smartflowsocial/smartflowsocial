# v1.0.0-beta.1

**Status:** prerelease candidate. The GitHub Release and the git tag are not published.

**SmartFlowSocial v1 — Now Open Source.** This is the first coordinated open-source release of
SmartFlowSocial: a Nostr-native publishing platform you can run yourself or use as a hosted service.
The product was in open beta before the source was published. This is not a first launch and not a
stable `1.0.0`.

`v0.1.0-alpha.0` and a withdrawn `v1.0.0` were published from an earlier repository on 14
November 2026. They are not supported releases of `smartflowsocial/smartflowsocial`. Local notes for
`0.1.0-alpha.1` through `0.1.0-alpha.3` were prepared in this repository and were not published as
GitHub releases. Those notes stay as written.

## What this prerelease is

1. **Nostr-native.** You sign events with your own NIP-07 or NIP-46 signer. The server stores the
   signed event and publishes it later. It does not need your Nostr private key.
2. **Open source and public domain.** The code is under the [Unlicense](../../LICENSE).
3. **Self-hostable.** `SELF_HOSTED=true` turns hosted plan limits off for the software you run and
   sets the platform campaign commission to 0% on every plan. No platform-fee invoice is created.
4. **Hosted option available.** The hosted service at [smartflow.social](https://smartflow.social)
   is the same application. Hosted campaign commission is Free 10%, Starter 7.5%, Creator 5%, and 0%
   on Pro, Teams, and Founder.

The hosted service is operated centrally. Scheduled signed events are stored until publication.
Hosted services may process metadata and media. An independent deployment does not depend on the
hosted operator for scheduling.

## What changed in this candidate

- Owned media deletion is queued in `OwnedObjectDeletion` before the account row is removed. The
  worker retries those keys after a storage outage or a process restart. Shared objects, foreign
  keys, and Blossom blobs this install does not control are left in place.
- Blossom `/ready` no longer treats every `HeadObject` error as the same boolean, and a missing
  probe object is healthy. The live endpoint on 17 November 2026 still returned `storage: false`
  without `storageError`. That production failure is **unverified** until the new build is deployed
  or the operator runs
  [the R2 check](https://github.com/smartflowsocial/smartflowsocial-blossom/blob/main/docs/ops/r2-readiness.md).
- `pnpm test:worker` in the publisher repository runs the Worker in `wrangler`'s local runtime
  against a loopback Nostr relay. It is separate from `pnpm smoke:publish` and from
  `pnpm test:relay-publish`.
- Blastr production publish is manual. Staging is configured to use `blastr-publish-jobs-staging` so
  it does not consume the production queue. The queue has to be created before the next staging
  deploy. The currently deployed workers were not changed.
- Publisher, Blossom, Blastr, and the cache worker have a Gitleaks workflow. It is not active until
  those commits are on the default branch.
- Incoming NWC lookups now say whether settlement was proven with a preimage or only reported by the
  wallet. Omitting the amount or the payment hash does not by itself reject a settled lookup.
  Outgoing payouts still require a matching preimage.

## Upgrade

Apply migrations with `pnpm exec prisma migrate deploy`. The new migration is
`20261117220000_owned_object_deletion`.

`SELF_HOSTED` is still read from the server environment. A request header, cookie, or query
parameter cannot select it.

`REFERRAL_PAYOUTS_ENABLED` must be `true`, `1`, or `yes` or referral payouts stay off. `OWNER_NWC`
does not turn them on.

Publisher `ALLOW_PRIVATE_RELAYS=true` does nothing unless `ENVIRONMENT` is `test` or `development`.
A production worker keeps the private-network block.

Do not deploy Blastr staging until `wrangler queues create blastr-publish-jobs-staging` has been run
in that Cloudflare account. Do not deploy production from the manual workflow until you mean to.

## Known limitations

- `1.0.0-beta.1` is a prerelease. CI on `main` before these edits is not evidence that production is
  running this commit.
- Production component SHAs were not read from the running services. They are unknown.
- Blossom `https://blossom-api.smartflow.social/ready` returned HTTP 503 with `storage: false` on 17
  November 2026. `/health` returned HTTP 200. No R2 credentials were available here, so the storage
  error class is unverified. See the Blossom ops note. Do not describe this as fixed in production.
- The app's relay smoke uses `scripts/relay-publisher.mjs`. That process writes to a loopback relay.
  It is not the Cloudflare Worker. The Worker check is `pnpm test:worker` in the publisher
  repository. The full path from the app through the deployed Worker to a relay was not run.
- Externally hosted Blossom objects are not deleted by account deletion.
- The hosted service does not claim GDPR compliance. The public contact is
  `npub1ckqlguq0htvs3smwy8pl5uwmfas0h208p7p8hs92ghaurgkmzzrsw3vlh0`. That is not a legal name or
  address. The owner has accepted that gap for the hosted service. It does not block publication of
  the self-hostable source.
- `GET /cron/purge-retained-records` still runs the purge when the cron secret matches, and the
  response sets `Deprecation: true`. The production scheduler was not inspected, so the method was
  not removed.
- Live `https://smartflow.social/pricing/` was read on 17 November 2026 and states the same hosted
  commission rates as the application. The landing source for that copy is
  `fix/hosted-commission-copy`. It is not part of the app tag.

## Owner checklist

1. Compare this manifest with the commits you are willing to tag. Commit the release work on review
   branches. Do not include the duplicate files.
2. Verify production R2. From a shell that already has the Blossom R2 variables, follow
   `smartflowsocial-blossom/docs/ops/r2-readiness.md`. Do not print the secret key.
3. Record the commit actually deployed for the app, publisher, Blossom, Blastr, cache worker, and
   landing. CI being green does not prove that.
4. Run one controlled publisher test against the deployed worker with an ephemeral key and a relay
   you control. Do not use a production account.
5. Confirm backups restore, and confirm the Cloudflare token cannot do more than this deploy needs.
6. Confirm organization 2FA and that GitHub rulesets match
   `docs/guides/organization-security-checklist.md`.
7. Create `blastr-publish-jobs-staging` before any staging deploy. Leave production on
   `blastr-publish-jobs`.
8. Read the hosted-service legal exposure in `docs/legal/hosted-service-disclosures.md` and accept
   it or change the hosting terms. Do not invent an operator name.
9. Set the GitHub repository description and remove a stale `remix` topic if it is still present.
   The framework is React Router 8.5.1.
10. Publish `v1.0.0-beta.1` as a **GitHub prerelease**. Do not mark it latest-stable.

## Draft GitHub Release

Title: `v1.0.0-beta.1`

### Overview

SmartFlowSocial v1 — Now Open Source.

The first coordinated open-source release of SmartFlowSocial: a Nostr-native publishing platform you
can run yourself or use as a hosted service. The product was already in open beta. This tag does not
mean the project just launched, and it is not a stable 1.0.0.

### Major functionality

Schedule and batch-publish notes you sign with your own NIP-07 or NIP-46 signer. The server stores
the signed event until it is time to publish. Long-form notes, media metadata, analytics, and
Lightning-powered campaigns and giveaways are in the same application. Blossom, Blastr, and the
cache worker are separate repositories.

### Open source and licensing

The source is released under the Unlicense and is in the public domain. `package.json` stays
`"private": true` so the package is not published to npm. That flag does not make the GitHub
repository private.

### Self-hosting

Clone the repository, install Node.js 22.22 or newer and pnpm 10.27.0, and follow
`docs/getting-started/self-host-smoke.md`. PostgreSQL and Redis are required. Set `SELF_HOSTED=true`
on an install you operate. Platform campaign commission is then 0% on every plan. Blossom, Blastr,
and the cache worker are optional.

`pnpm test:relay-publish` checks that a scheduled signed event reaches a loopback relay through the
in-repo publisher. `pnpm test:worker` in the publisher repository checks the Cloudflare Worker
runtime. Those are different checks.

### Hosted service

The hosted service runs this application. It is centrally operated. Signing keys stay in your
signer. The hosted service stores signed events until publication and may process metadata and
media. Hosted campaign commission is Free 10%, Starter 7.5%, Creator 5%, and 0% on Pro, Teams, and
Founder. Winner payouts come from the creator's wallet.

### Known limitations

This is a prerelease. Production deployment SHAs were not verified as part of the tag. Blossom
readiness at `https://blossom-api.smartflow.social/ready` was HTTP 503 with storage not ready on 17
November 2026; treat that as an operator check, not as a closed incident. Account deletion does not
remove blobs from a Blossom server this deployment does not operate, and it does not remove events
relays have already accepted. The hosted service does not claim full GDPR compliance. The public
contact is `npub1ckqlguq0htvs3smwy8pl5uwmfas0h208p7p8hs92ghaurgkmzzrsw3vlh0`.

### Security
